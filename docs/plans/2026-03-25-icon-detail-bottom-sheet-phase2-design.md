# Icon Detail Bottom Sheet Phase 2 Design

**Date:** 2026-03-25
**Status:** Approved

## Goal

아이콘 상세 바텀시트를 읽기 전용 1차 상세뷰에서 한 단계 확장해, 카드 클릭부터 시트 진입/퇴장, 배경 처리, 반시트 레이아웃, 메타데이터 편집 진입, 키라인 검토 도구까지 포함한 전체 경험을 정교하게 다듬는다.

## Product Intent

현재 1차 바텀시트는 기능적으로는 충분하지만, 상세 모드로 진입했다는 감각과 정보 위계, 메타데이터 관리 진입점이 아직 약하다. 2차에서는 다음 세 가지를 분명하게 만든다.

- 상세 검토는 `반시트`라는 별도 모드로 인식되어야 한다.
- 원본 SVG 검토, 웹폰트 프리뷰, 빠른 액션, 메타데이터 관리는 한 흐름 안에서 연결되어야 한다.
- 메타데이터 편집은 바텀시트 전체를 무겁게 바꾸지 않고 섹션 단위 편집으로 확장되어야 한다.

## Scope

### In Scope

- 카드 클릭부터 바텀시트 등장/퇴장까지 포함한 전체 경험 polish
- 데스크톱 기준 큰 `반시트` 레이아웃으로 조정
- 클릭된 카드의 약한 active 강조
- 배경 dim/blur 강화
- 바텀시트 헤더, 정보 위계, 빠른 액션 재배치
- 메타데이터 섹션의 부분 편집 모드
  - displayName
  - category
  - keywords
  - synonyms
- 명시적 저장/취소 UX
- 변경 감지 및 unsaved 상태 처리
- 키라인 오버레이 고도화
  - 외곽 프레임
  - 중심선
  - 원형 가이드
  - safe area 사각형

### Out of Scope

- 동시 편집 충돌 해결
- 다중 사용자 협업 편집
- SVG path 기반 자동 정렬/검증
- 아이콘 비교 뷰
- 메타데이터 히스토리/버전 관리

## Approaches Considered

### Option 1: Progressive Detail Sheet (Recommended)

기존 1차 바텀시트를 유지하되, 전체 경험을 polish하고 메타데이터 편집을 섹션 단위로만 확장한다.

**Pros**
- 현재 구현 위에 자연스럽게 확장 가능
- 탐색 흐름을 유지하면서 상세 모드만 분명하게 만들 수 있음
- 편집 범위를 제한해 저장 UX를 제어하기 쉬움

**Cons**
- 상세 모드 안에 정보와 액션이 많아져 위계 설계가 중요함

### Option 2: Full Editor Sheet

상세 시트 전체를 편집 중심으로 재구성하고, 읽기 모드보다 저장 UX를 앞세운다.

**Pros**
- 관리 툴로서 강함

**Cons**
- 라이브러리 탐색 흐름과 충돌
- 읽기와 편집의 목적이 섞여 시트가 무거워짐

### Option 3: Separate Inspector Page

상세를 바텀시트가 아니라 별도 Inspector 페이지로 분리한다.

**Pros**
- 복잡한 편집 UI 수용이 쉬움

**Cons**
- 라이브러리 맥락이 끊김
- 현재 제품 성격보다 과함

## Recommendation

Option 1을 채택한다. 1차의 읽기 중심 상세 시트를 유지하면서, 반시트 경험을 강화하고, 메타데이터는 섹션 단위 편집으로 확장한다.

## UX Structure

### 1. Entry and Transition

- 카드 클릭 시 선택 카드가 살짝 강조된다.
- 배경에는 현재보다 한 단계 진한 dim + blur를 적용한다.
- 바텀시트는 아래에서 올라오는 큰 반시트로 전환한다.
- 닫힐 때는 같은 경로로 부드럽게 내려간다.

### 2. Half-Sheet Layout

#### Desktop
- 높이: 약 `82vh`
- 상단 여백이 남아 라이브러리 배경이 살짝 보인다.
- 2열 구조 유지
  - 좌측: 원본 SVG + 키라인
  - 우측: 정보 + 액션 + 프리뷰 + 메타데이터

#### Mobile
- 거의 풀 높이에 가까운 시트
- 상단 핸들/헤더 유지
- 내부는 세로 스택

### 3. Header

- 좌측: 아이콘명, 카테고리/타입 보조 정보
- 우측: 닫기 버튼
- 헤더는 식별과 닫기만 담당하고, 빠른 액션은 본문으로 내린다.

### 4. Left Panel: Source SVG

- 큰 정사각 1:1 캔버스 유지
- `키라인 보기` 토글 유지
- 키라인 고도화 시 다음 레이어 표시
  - 외곽 프레임
  - 중심선 십자
  - 원형 가이드
  - safe area 사각형

### 5. Right Panel: Webfont Detail

정보 위계는 아래 순서를 따른다.

1. 식별 정보
   - glyph key
   - class key
   - 카테고리
   - 타입
2. 빠른 액션
   - 글리프 복사
   - SVG 다운로드
3. 웹폰트 크기별 프리뷰
4. 메타데이터

### 6. Metadata Editing

기본은 읽기 전용이며, 메타데이터 섹션만 부분 편집으로 전환한다.

- 편집 버튼으로 진입
- 편집 대상
  - displayName: 단일 입력
  - category: 드롭다운
  - keywords: 토큰 입력
  - synonyms: 토큰 입력
- 저장/취소는 명시적 버튼으로 처리
- 변경사항이 있으면 unsaved 상태 표시
- 닫기 시 변경사항이 있으면 확인 단계 제공

## Interaction Rules

- ESC, 바깥 클릭, 닫기 버튼으로 시트 닫기
- 시트 열림 동안 배경 스크롤 잠금 유지
- 포커스는 시트 안에 머물도록 유지
- 저장 성공/실패는 기존 토스트 시스템 재사용
- 빠른 액션은 읽기 흐름을 방해하지 않도록 2개만 전면 노출

## Data Flow

- 선택된 카드 key를 기준으로 상세 상태 유지
- 메타데이터 편집 시 로컬 편집 상태를 별도로 둔다
- 저장 시 `icon-metadata.json` 갱신 API 호출
- 저장 성공 후 `state.icons`와 상세 표시 내용을 동기화
- 키라인은 SVG path 분석이 아닌, 정사각 캔버스 위의 디자인 가이드 오버레이로 유지

## Accessibility

- 반시트는 계속 `role="dialog"`와 `aria-modal="true"` 유지
- 제목, 보조 설명, 편집 상태가 스크린리더에 전달되도록 구조화
- 편집 필드는 라벨과 설명을 함께 제공
- 모바일/데스크톱 모두 터치 타겟 44px 이상 유지

## Risks

- 상세 정보와 편집 UI가 섞여 복잡해질 수 있음
- 키라인 고도화가 실제 SVG 검토 도구로 오해될 수 있음
- 저장 API 추가 시 로컬과 배포 환경 차이가 더 커질 수 있음

## Mitigations

- 빠른 액션을 2개만 전면 노출하고 나머지는 보조 위치 유지
- 키라인은 `검토용 오버레이`라는 설명을 유지
- 편집 범위를 메타데이터 4개 필드로 제한
- 저장은 명시적 action으로만 처리
